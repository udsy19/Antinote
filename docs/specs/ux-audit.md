# UX audit — end to end

Every flow walked with one question: does anything get between the person and the note? Issues are fixed in the
same change unless the status says otherwise. Behaviour is covered by self-tests (`.build/debug/SuperNotesSelfTest`),
visuals by offscreen renders (`.build/debug/SuperNotesRender <dir> <scene-prefix…>`).

| Flow | Issue found | Fix | Status |
| --- | --- | --- | --- |
| Typing, undo | ⌘Z corrupted the text in list notes and then did nothing: the text view's range-based typing coalescer lost track when the editor rewrote a list marker or shortened a link inside a keystroke. No ⌘Y. | The editor records its own history (`NoteHistory`): whole-state steps, typing grouped per word, named steps for every command, one history per note, a hidden Redo twin on ⌘Y. Vim `u` / ⌃R use it; ⌘Z after Delete Note restores the note. | Fixed — `UndoTests.swift` (typing, list notes, commands, per-note, autosave, Vim, delete) |
| Delete a note | Three names for one action ("Delete Note", "Send to The Void", "banished to void"); the confirmation's button said "Send to The Void"; nothing said it could be undone. | One verb: menu "Delete Note", palette "Delete Note", pills "Note deleted" / "N notes deleted", alert "Delete this note?" with a Delete button, pill "Note deleted · ⌘Z to undo". | Fixed — `ShellKit.undoDeleteNote` |
| The Void | Restore was an unlabeled arrow icon; "lost souls", "Lost 3 hours ago", "(Empty vessel)", "Return", "There is no recovery beyond The Void." | A labeled Restore button per row, "Deleted 3 hours ago", "4 deleted notes", "(Empty note)", Done, "This can't be undone." Empty state says what the place is for. | Fixed — renders `void-list`, `void-empty` |
| Top / bottom bars | A bar revealed by a resting pointer stayed over the text while typing. | A plain keystroke in the note takes both bars down; they come back once the pointer really moves (4 pt). | Fixed — `HoverBar.typingStarted` |
| Message pills | The editor's pill sat at the bottom even when the caret's line was down there, covering what was being typed. | The pill moves to the top (below the title bar) while the caret's line is in the pill's strip. | Fixed — `EditorKit.pillAvoidsCaret` |
| Pill copy | Mixed endings ("Extracted text.", "Pasted content optimized."), system-side wording ("Cannot partially edit shortened links. Expand before editing."), and "Calculated results can't be edited." with no way out. | No trailing periods; say what to do: "Click the link to expand it before editing", "“Prevent editing answers” is on in Settings → Keywords", "Pasted text cleaned up", "Text captured", "AutoPaste on · Esc stops", "Couldn't read that image. Try copying and pasting it". | Fixed |
| Move to front | Menu "Move Note to Front", palette "Promote to Front", pills "Promoted note to front" / "Note is already first" / "Slotted notes don't have a front position". | "Move to Front" everywhere; pills "Moved to the front", "Already at the front", "Slotted notes stay in their slot". Pin: "Pinned on top" / "Unpinned" in both places. | Fixed |
| Timers | A finished timer's full-screen alert activated Super Notes and took the keyboard mid-sentence in another app. | The alert comes forward without taking focus; clicking it (or Nice / Esc once it's clicked) dismisses it. Break, breathing and live screens, which you ask for, still take focus. | Fixed — `TimerOverlay.present(takesFocus:)` |
| Menus | Support and Help menus listed the same two items. | One Help menu. A self-test checks the menu bar order and that no two visible items share a shortcut (⌘Y lives only on the hidden Redo twin). | Fixed — `ShellKit.menuShortcutsUnique` |
| Settings → Appearance | "Show note modified/created time" and "Show the note creation date" read as the same thing; the first adds the time of day, the second switches to the creation date. | "Show the time of day next to the date", "Date the note by when it was created, not last changed". | Fixed — render `settings-full-appearance` |
| Onboarding | Final note: "⌘D Send a note to The Void". | "Delete a note (it waits in The Void)". | Fixed |
| First launch + tutorial | Tutorial notes seed once, walk back with ⌘[ hints, keyword demos live. | — | OK as is |
| Show / hide with ⌥A | `showMain` → `focusActive` puts the caret back in the text view, which keeps its selection. "Create a new note after" is a setting (Never by default). | — | OK as is |
| Keyword modes | Math results are drawn after the line (annotations), never inserted; ⌥-click inserts one on purpose. Return on an empty item ends the list (`Lists.continued`); an indented empty item outdents first. | — | OK as is |
| "/" and "::" lists | The "/" list opens only at the start of a line or after a space, with letters and digits after it; never in URLs ("https://"), fractions ("1/2") or paths with no matching command. Esc closes it and remembers the dismissal for that "/". `::` likewise. Neither takes the focus; the mouse works. | — | OK as is |
| Find bar | ⇧⌘F docks the shelf; Esc / Done close it and put the focus and the found match back in the text. | — | OK as is |
| Swiping, ⌘[ / ⌘] | Past the newest note a new one is created with a "New note created" pill; "This is the oldest note" / "Already at latest" otherwise. Non-blocking. | — | OK as is |
| Slots bar | The planets bar came up with the bottom bar whenever the pointer drifted low, and sat over the last lines while they were being typed; always-show kept it there through typing. | `SlotBarVisibility`, one state machine: hidden by default; up once the pointer has rested in the bottom 28 pt for 250 ms, for 2 s after a slot is used, or always with "Always show the slot bar" — and never while typing: a keystroke takes it down (150 ms fade) until the pointer moves back into the strip, or 2 s of quiet with always-show. After a keystroke the pointer must move 4 pt to count, so a hand on the trackpad never flickers it. It floats over the note; the note's bottom inset is reserved only with always-show, so text never shifts. | Fixed — `ShellKit.slotBarVisibility`, `ShellKit.slotsShell`; renders `window-slots-rest`, `window-slots-typing`, `window-slots-hover(-dark)` |
| Opening a slot | No sign of what had happened beyond the planet changing colour; the slot pane took the focus with a stray `makeFirstResponder` on the editor's root view; in the split, a swipe with the slotted note focused moved the deck. | Two places, one model: the deck (your stream of notes) and nine slots. Opening a slot shows its note in place with a 150 ms fade (220 ms slide when swiped) and "Slot 3 · <title>" above its planet for 2 s; the deck note stays in its own pane, caret and scroll position untouched, and Esc, ⌃⌘0 or the Back to Notes item returns to it. Swiping, ⌘[ / ⌘], Previous/Next Slot move through the slots in use only (`SlotNavigator`), in order; at either end the note nudges 6 pt back and the planet says "First slot" / "Last slot". Nothing is ever created from a slot. | Fixed — `ShellKit.slotNavigator`, `ShellKit.slotsShell`; renders `window-slot-open(-dark)` |
| Slot shortcuts | Go to Slot ⌘1…⌘9 existed only behind a Settings switch (hidden otherwise); Assign used ⌃⌘1…9; nothing said how to get back. | Always there: Go to Slot 1…9 ⌃⌘1…⌃⌘9, Previous Slot ⌃⌘[, Next Slot ⌃⌘], Back to Notes ⌃⌘0 (and Esc, when the note has no use for it: no list open, not Vim), Put in Slot ▸ ⌥⌘1…⌥⌘9, Remove from Slot. The "⌘1–⌘9 jump to slotted notes" switch drops the ⌃ (⌘1…⌘9, ⌘0). Every shortcut is in the menu, rebindable, and the planet tip says it: "Slot 3 — Groceries · ⌃⌘3"; the open planet: "Click or press Esc to go back to your notes"; an empty one: "Click or press ⌥⌘3 to put this note here". | Fixed — `ShellKit.menuShortcutsUnique`, `ShellKit.slotBarTip` |
| Putting a note in a slot | Assigning reloaded the note in the other pane with the caret at the end; assigning to its own slot silently removed it; replacing an occupied slot had no way back. | From the menu (Put in Slot ▸), the planet's right-click menu ("Open Slot 3", "Put This Note in Slot 3", "Remove “Zeus” from Slot 3") or a click on an empty planet. The note keeps its caret across panes. Replacing an occupied slot just does it and says "In slot 3 · ⌘Z puts “Zeus” back"; removing says "Back in your notes · ⌘Z undoes"; ⌘Z (Undo Move to Slot) puts every note back where it was. Putting a note in its own slot says "Already in slot 3". | Fixed — `ShellKit.slotsShell` |
| Search inside the window | Search placed its Select \| Ephemeral and list / cards capsules 14 pt up the bottom strip, where the window's hover bottom bar also lives: the pointer resting there brought Delete / Previous / Next / Latest / Export up over them, tooltips and all. The corner buttons didn't share one geometry either (top bar buttons touching, bottom bar buttons 8 pt apart; capsules 16 pt in, bars 10 pt). | One size system, `ChromeMetrics` (30 pt buttons, 22 pt glyphs, rows 20 pt from the edges, 10 pt side insets, 8 pt gaps), for the top bar, the bottom bar and Search's capsules. A mode with its own bottom controls owns the strip: while Search or the find shelf shows, `Shell.bottomStripTaken` keeps the bottom bar, the slot bar and the latest-note dot down. Narrow windows degrade in order: text, Export, First in the bottom bar; the Typing button in a window too narrow for both groups; Search's labels (glyphs stay). | Fixed — `ShellKit.chromeMetrics`, `ShellKit.chromeNoOverlap` (no two controls intersect in note, slot, locked, slot-bar, Search list / cards / Select and find-shelf modes at 240, 350, 600 and 1200 pt); renders `window-search-list-350(-dark)`, `window-search-cards-350`, `window-search-select-350`, `window-search-list-240`, `window-search-list-1200`, `window-search-cards-1200(-dark)`, `window-find-shelf(-1200)` |
| Reading a narrow note | Text sometimes ran off the right edge until the window was widened. Two causes: a list item indented past the column (seven tabs, or two dozen spaces, in a 240 pt window) made TextKit lay the paragraph out one glyph per line parked on the edge, so the item vanished; and a math result or error too wide for the column was drawn from the column's start on its reserved row and ran past the edge (at XL double text a 240 pt window has a 110 pt column). | A hanging indent never takes more than half the column (`EditorLogic.Annotations.hangingIndent`). A result that doesn't fit after its line gets as many rows under the line as it needs, right-aligned against the column's edge and wrapped inside the column (`EditorTextView.resultRows`). The container keeps tracking the view in every mode, with no horizontal resizing or scroller. | Fixed — `EditorKit.softWrap` (the real editor at 240, 350 and 600 pt, resized between them, in plain, list, math, code, sum, timer and markdown notes with a long URL, a 300-character word, big results, a seven-tab indent, links expanded, XL double text: every fragment, glyph and result inside the column, no sideways scroll); renders `editor-wrap-plain/math/list/code-240(-dark)`, `editor-wrap-math-350` |
| Top bar next to the traffic lights | `ChromeMetrics` assumed macOS 14 / 15's traffic lights (close at 7, 20 pt pitch, zoom ending at 61) and put Settings one 8 pt gap after that, at 69 — on macOS 26 the lights sit at 9 / 32 / 55 and the zoom button ends at 69, so the Settings hover square touched it and the glyphs crowded the lights. | The window measures its real traffic lights (`MainWindow.measureTrafficLights` → `ChromeMetrics.trafficLights`, the single source of truth) and the left group starts two gaps (16 pt) after the zoom button: the glyph is 20 pt from it, more than the 16 pt between glyphs, so lights and buttons read as two calm groups; buttons stay centred on the lights' line, 8 pt apart, the right group 10 pt in. Typing gives way when both groups can't fit (`ChromeMetrics.topBarWidth`). | Fixed — `ShellKit.chromeMetrics` (both releases' lights), `ShellKit.chromeNoOverlap` (measured lights carried, buttons ≥ 16 pt from the zoom button and on its centre line, equal gaps, at 240–1200 pt in every mode); renders `window-revealed(-dark)`, `window-bottombar-240`, `window-typing-menu(-dark)` |
| Typing options | Spelling and text replacements lived only in Settings; autocorrect, capitalisation, smart quotes and dashes and grammar had no switch at all (quotes and dashes were hard-wired off). | A Typing button in the top bar with a checkmark menu (`TypingMenu`, one item per `TypingOption`), the same rows in Settings → Editor → Typing, and the text view's context-menu toggles writing the same keys. Defaults: spelling on, the rest off. Code notes are never checked, code and math notes never substituted or capitalised; the menu's footer says so. Capitalisation is the editor's own rule (`EditorLogic.Capitalization`), so it never touches URLs, paths, "e.g." or "iPhone". | Fixed — `Settings.typingOptions`, `EditorKit.autoCapitalize`; renders `window-typing-menu(-dark)`, `glyph-icon-typing` |
| Locked notes | Lock screen with a labeled Unlock button; relock timing in Settings → Notes. | — | OK as is |
| Export, print | "Note exported", "No note to print", "Choose a Quick Export destination in Settings → Export". | — | OK as is |
| Settings | Sentence-case labels with captions; every control bound to a default; no dead controls found in a pass over all panes. | — | OK as is |
| Window | Min size 240 × 180, frame remembered (not in dropdown mode), pin on top, translucency behind the note. | — | OK as is |
| Settings, search and palette fields | Standard field editors; the Edit menu's nil-targeted Undo / Redo reach them through their key panel. | — | OK as is |

## Not changed, on purpose

- The delete confirmation stays (it can be suppressed with "Don't ask again"): ⌘Z now covers the common slip, the
  alert covers the deliberate one.
- Keyword and command names keep their established vocabulary ("The Void", "Ephemeral", slots as planets); the
  audit changed what was inconsistent or unlabeled, not what gives the app its character.
